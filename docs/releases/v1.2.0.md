# FrameGeist v1.2.0 —— 官方点缀色面能力 + 字标墨迹居中

发布日期：2026-10-01（本文件为随版本推进实时更新的发布说明）

## 1. 背景：把「补齐官方素材」这件事查到底

v1.1.0 用你交付的官方素材替换了 22 个品牌徽标后，还剩两批没有官方素材：

- 13 枚镜头系列徽章（v1.1.0 移除 `canon-rf-l` 后实为 12 枚，已落地 `nikon-s`，**待补 11 枚**）；
- 6 个游戏字标。

`docs/reports/v1.2.0/series-game-materials.md` 逐项取证后的结论：

| 建议动作 | 数量 | 项目 |
|---|---|---|
| `ingest-official` | 4 | `zzz` / `honkai` / `wwmeet` / `wukong`（仅 Steam 商店 capsule 图，**231×87 偏糊**） |
| `keep-mono` | 13 | 11 枚系列徽章 + `genshin` + `arknights` |
| `recolour-with-accent` | **0** | **没有任何一项能从官方页面取到可套色的点缀色** |

硬证据：

- Sigma 的 ART 是纯 HTML 文字（`<p class="first-child">ART</p>`，页内 `<svg>` 0 个、`background-image` 0 个）；
- Tamron `sprite.svg` 逐符号枚举 81 个 `<symbol>`，唯一含 `logo` 的是母品牌，**无 SP**；
- HoYoverse 官网 4 个 `_nuxt/*.js`（1,055,178 字节）+ 官方 `footer.js`（81,485 字节）对
  genshin / zzz / honkai 的**图片引用数为 0**，Steam 无原神条目，Epic 商店页 403；
- 从 game 官网 favicon 采到的 `#F2850E`(zzz) / `#FFC62C`(honkai) 经占比检验**仅占 0.2% 不透明像素，属抗锯齿噪声**，
  按 v0.9 决策 1「颜色维持官方口径」不采用；
- 受限项如实标注为「不可达」而非「不存在」：`sony.com` 403、`fujifilm-x.com` 403 Cloudflare、
  `arknights.com` / `wwmeet.cn` DNS 不存在。

据此，v1.2.0 的口径是：**官方没有发布素材的品牌维持官方现状（单色），不臆造颜色、不用低分辨率图充数**；
同时把「素材到位就能立刻上色」的引擎能力与门禁补齐。

## 2. 引擎：官方点缀色面（`-accent`）

系列徽章在仓库里一直是单色资产，引擎的彩色分支要求主资产自身带色
（`render.rs` 的 `primary_colorful = chroma >= 0.25`），因此 manifest 里的官方点缀色永远到不了画面。

v1.2.0 新增可选的 **`<slug>-accent.png` 面**：

- 判定逻辑抽成**纯函数** `render::pick_badge_face(mode, tint_hint, primary_colorful, scores, available, want_light) -> BadgeFace`，
  配 `BadgeFace{Primary, Accent, Mono, Light}`、`BadgeScores`、`BadgeAvailability`、`BADGE_COLOR_FLOOR = 3.0`；
- accent 面是**官方单色标识的纯上色**，几何与 mono 面逐像素一致 → **排版零位移**；
- 只有当 accent 对**局部背景**达到 WCAG 1.4.11 的 3:1，或图层显式 `tint: "color"` / `contrast: "color"` 时才使用，
  否则自动回退黑白（Nikon 黄这类正是如此）；
- 资产矩阵：`brand` 三面 + `-accent` 可选；`series` / `game` 现有两面 + `-accent` 可选。
  没有 `-accent` 文件时行为与 v0.9 完全一致，pre-v0.9 单面资产集仍回退主资产。

测试 `crates/framegeist-cli/tests/engine_v120.rs`（4/4）：

- `accent_face_policy`：决策表全枚举（彩色主资产保持旧行为、accent 达标/不达标、显式 color、单面资产兜底）；
- `accent_face_follows_local_contrast`：黄标暗底上屏、白底回退黑标；
- `strong_accent_survives_light_background`：红色 accent（对白底仍 >3:1）白底也上屏；
- `accent_face_keeps_mono_geometry`：accent 与 mono 的墨迹盒逐像素相同。

## 3. 字标墨迹居中（真实缺陷修复）

`tools/gen-brand-assets.mjs` 用 `dominant-baseline="central"` 排版，**居中的是 em 盒而不是墨迹**，
遇到升降部不对称的字体就会偏心。实测（`target/png-dims.mjs`）：

| 资产 | 修正前 padY | 修正后 padY |
|---|---|---|
| `game/wwmeet`（毛笔体中文） | 113 / 96（偏 17px） | 105 / 104 |
| `game/arknights`（Oswald） | 177 / 156（偏 21px） | 167 / 166 |
| `game/wukong` | 176 / 156（偏 20px） | 167 / 165 |
| `series/leica-apo` | 172 / 181 | 177 / 176 |
| `series/canon-l` | 174 / 183 | 179 / 178 |

同时修正水平偏心（`fujifilm-xf` 20/26、`hasselblad-xcd` 6/11、`sigma-apo` 2/7、`zeiss-batis` 83/76、`genshin` 30/22 等）。
改法：先渲染一次量墨迹包围盒，再把文字坐标偏移到墨迹居中（`inkOffset()`，结果按 slug 缓存）。

> 踩坑记录：`@resvg/resvg-js` 2.6.2 的 `RenderedImage.pixels` **在循环里惰性读取会让 node 静默退出**
> （exit 1、没有任何报错）。必须先 `Uint8Array.from(probe.pixels)` 复制一次再扫描。
> 这类「无输出崩溃」差点被误判成资源或字体问题，探针脚本 `target/probe-wordmark.mjs` 才定位到。

## 4. 门禁

`tools/check-brand-colors.mjs` 从 250 扩到 **268 项**（新增 18 项 `ink is centred in its canvas`，
覆盖 12 枚系列 + 6 枚游戏字标，容差 2px）。现在同时守住：

- 颜色口径（manifest v5 / `originalColorOverride` / `officialAsset`）；
- 宽字标墨迹高度 ≤ 0.34×画布高（v1.1.0 回归的护栏）；
- 字标墨迹在画布内居中 ≤ 2px（v1.2.0 新增）。

## 5. 工具链：resvg 子进程隔离（本轮附带修复）

`@resvg/resvg-js` 的绑定层**没有释放接口**（`Resvg.prototype` 只有 `constructor`），每次渲染在
Rust 侧分配的 fontdb/usvg tree **只有进程退出才归还 OS**，`global.gc()` 无效（实测 ≈ 1.2 MB/渲染）。
一次全库生成约 500+ 次渲染，曾把 `node.exe` 的提交内存推到 **128 GB**，导致系统内存耗尽与蓝屏。
事故报告：`docs/reports/v1.2.0/incident-resvg-leak.md`。

三个渲染工具改为**按资产子进程隔离**：

| 工具 | 子模式 | 说明 |
|---|---|---|
| `tools/gen-brand-assets.mjs` | `--render-one <kind> <slug> [--svg-file <path>]` | 每资产 1 进程；官方 SVG 由父进程抓取后经临时文件传入 |
| `tools/import-brand-inbox.mjs` | `--render-one <slug>` | 每品牌 1 进程；父进程继续独占 `brand-colors.json` / manifest |
| `tools/make-compare-sheets.mjs` | `--render-one <category>` | 每分类 1 进程 |

子进程成功时打印机器可读标记 `RENDER_OK …`，父进程解析后重建原有的 `iconSlugs` /
`iconCredits` / `wordCredits` / `lockupCredits` / 导入报告条目；**manifest 与 CREDITS 的写入
仍只在父进程**。隔离只改进程边界、不改任何渲染参数，因此**字节等价**（已逐一核对：5 个资产
SHA256 相同、zeiss 重导入字节相同、对比图 `game.png` 字节相同），同刻常驻内存峰值 167 MB。

## 6. 兼容性

- 模板、`meta.version`、`minEngineVersion` 全部未变；旧模板渲染**逐字节不变**；

- 设置键、manifest 字段只增不改（`web/brand/index.json` 仍为 manifest v5）。
