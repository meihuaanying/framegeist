# FrameGeist v1.5.0 — 安全加固与发布链修复

发布日期：2026-10-10

## 1. 这一版修的是什么

v1.4.0 为 12 枚镜头系列徽标补齐了模板，但一次全仓审计暴露出两类问题：**模板沙箱有多个可被模板文本单独触发的逃逸与崩溃**，以及**发布链路本身不校验结果**。v1.5.0 共修 21 项，全部带回归测试，且没有改变任何一套模板的渲染像素（视觉基线 408/408 零漂移，未使用 `--update`）。

## 2. 模板沙箱（P0，4 项）

- **infoBlock 表达式未校验 → 渲染器 panic**。`validate_exprs` 只遍历文本层，信息块的行原样进入求值器，`if_empty` 与 `fmt` 分支按下标切片字符串。三个 payload（`if_empty(exif.model, )`、`if_empty(exif.model, x)`、`fmt(')`）均让 CLI 以 exit 101 崩溃。现在加载期逐行校验、求值期对畸形输入一律返回空值。
  28 套模板把多个表达式用 ` · ` 拼在同一行上；求值器对这种序列返回空值、这些行一直渲染 fallback，因此**拒绝或支持拼接都会改变渲染结果**。校验侧新增了引号感知的分词，渲染语义一字未动。
- **资产路径沙箱逃逸**。字符白名单放行 `{`/`}`，`assets/{exif.make}` 原样通过校验，随后由相机控制字节替换、读取资产目录之外的文件。现在占位符限定为三种 slug，读取前对两侧做规范化并做包含性判断。
- **`sandbox::check` 拦不住穿越与外来 scheme**。反斜杠、裸 `..`、盘符、UNC、`%2e%2e`、`data:`/`javascript:`/`blob:` 等均可穿过。已按路径段与 scheme 白名单重写，并加入单串长度上限。刻意**没有**采用「含 `:` 即为 scheme」的规则——模板里的 `f/{aperture}`、`HH:mm` 与 `'12:30'` 会被误杀。
- **自由拼图内存放大**。边长上限与条目分数相乘，几百字节的 JSON 即可申请约 1 GB 缓冲区，旋转步骤再叠加一块。现在画布与单条目都有像素预算，四分之一转走精确轴交换、不再分配方形暂存区。

## 3. Web 端（P1，8 项）

模板墙的 IntersectionObserver 在每次按键时重建且从不释放；保存模板只遍历顶层文字层、从不写回信息块，导致保存出的文件与画布不一致；service worker 缓存未命中时必然发起第二次请求；`{tplName}` 永远输出模板 id；灯箱异步竞态会让旧请求覆盖新图；`localStorage` 里的非法语言值会让整个 UI 空白；三处硬编码字符串在英文界面下露中文；77 处控件与图标按钮缺少可访问名称，两个模态对话框没有焦点管理。

## 4. 加固（P2，8 项）

画布尺寸加法改饱和运算；PNG EXIF 写入前断言首块类型与长度边界；EXIF 擦除从 O(wipe×keep²) 降为 O((W+K) log K)；水印预设与墙徽标改走文本/编码赋值，导入模板限制 id 形式；service worker 与页面版本号改为同源；manifest 补齐 192/512 与 maskable；桌面端自行校验导出路径（分隔符、Windows 设备名、绝对路径与包含性）；新增 `tools/check-all-gates.mjs` 一键串行跑全部门禁。

## 5. 顺手修掉的一个真实缺陷

新增的保存往返断言抓到一个清单外的缺陷：保存模板时以**原始** JSON 为基底，而画布编辑器的图层列表存在本地存储、只在渲染时合并。实测某模板画布渲染 8 层、保存出的文件只剩 1 层，重开会得到不同尺寸的画布。UI 无任何提示。

## 6. 发布链修复

v1.4.0 的发布产物是从一棵与仓库不一致的树构建的：12 个系列模板缺失，`update.json` 对外宣称 192 套而仓库定义 204 套。原因是推送工具以**从未推送过的本地提交**为基准做增量，并从工作区读取字节（Windows 下为 CRLF），导致远端树等于旧基线加一段不完整增量——所有工作流、部署与 ref SHA 单独看都正确，唯独「远端树是否等于目标树」能发现问题。该检查现已内建于工具，并在移动分支前中断。

本次发布通过 Git Data API 重建了远端树：122 个 blob、30 个目录树重建，其余 67 个目录按 sha 复用，验证后与本地 HEAD 在非 `.github` 路径上**零差异**。

## 7. 已知限制

远端 `.github/workflows` 缺失：当前 token 没有 `workflow` scope，GitHub 会把任何包含 `.github` 的 ref 更新以 404 拒绝（这不是权限提示，而是被遮蔽的拒绝）。workflow 文件内容仍可从 `v1.4.0` tag 取回，补齐 scope 后一即可恢复 CI、Pages 与自动发版。本次发布因此改为本地构建六资产并上传。
