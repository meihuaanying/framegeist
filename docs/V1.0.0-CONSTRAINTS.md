## 0. 问题实证（2026-09-23 侦察结论，全部有代码/CDP 证据）

用户原始诉求（原话，五条）：

1. 「目前元素模块里面选择元素或者图层的时候实物和识别框差了很远，一点击某个图层预览图就被挤出屏幕外面了。」
2. 「徽标有很多做得不符合官方设计，必须全部根据官网的官方logo一一核对样式是否正确，建议在官网和官方微信公众号上寻找官方的品牌徽标和镜头徽标。」
3. 「目前的字体大小和布置仍然不符合美学设计，文字全部放在图片的一侧，要么集中在左侧要么集中在下侧，文字允许三行以内自由排布，文字大小应该取正好填满空白部分2/3的高度（在下侧时）或宽度（在左侧时）。」
4. 「目前仍然无法使用鼠标直接在预览图上选择元素或者图层对象。」
5. 「调研同类产品是怎么做的，对照我们目前的产品，从功能和艺术设计上提出改善建议。」

| # | 问题 | 实证（CDP 实测） |
|---|---|---|

## 2. 红线（v0.9.3 之上新增/沿用）

- 沿用：零上传 / 0 账号 / 离线可用 / GPS 默认剥离 / 不引入商业字体 / 不碰 `D:\FrameLoom`。
- **禁止用 PowerShell `Set-Content/Out-File` 改写含非 ASCII 的仓库文件**；统一 Edit 工具或 Node 脚本；发布前必跑 `node tools/check-utf8.mjs`。
- **禁止修改 `.github/workflows/*`**；Release 说明用 `gh release edit --notes-file`；推送一律 `node tools/gh-api-push.mjs`（local-base 必须是本地存在的提交）。
- **不引入运行时框架/新依赖**（无 React/Konva/Fabric/tldraw）；DOM + Pointer Events + 现有引擎协议。
- **坐标单一事实来源**：任何几何消费方（overlay/命中/拖拽/缩放/旋转/吸附/导出裁剪框）必须使用**当前显示帧**的坐标；禁止混用「原图/预览/导出/全分辨率」帧。
- **选中不得自动平移**；画布主体必须始终留在视口内。
- **文字不得覆盖照片像素**；文字与徽标必须在同一留白区、同一侧（左/右/下）。
- **E2E 画布交互一律真实输入事件**；不得以合成事件自洽断言替代。
- 兼容红线：v0.7/v0.8/v0.9 全部能力与既有 E2E 断言不得回归（除按本契约**有意变更**的项：自动平移移除、E2E 改真实事件）；WASM↔CLI 帧字节一致；拼图 ≤0.1% 像素差；`fg-tpl-edits-v1` 只做增量字段（禁止破坏性改结构）。
- **DOM 兼容**：不得重命名 E2E 依赖的现有 id/class（`#layerList`/`#propsBody`/`#addText`/`#brandGroups`/`#brandLibGrid`/`#canvasWrap`/`.edit-overlay`/`.handle`/`.sidebar`/`.actionbar` 等）。
- 模板艺术文字、引擎日期、EXIF 单位与型号字样不改；用户自传模板原样。
- UX 红线：不可用「拖拽」作为唯一操作路径（WCAG 2.5.7）；所有拖拽/缩放手柄必须有键盘/数值替代（属性面板保留）。

## 3. 技术设计规范

### 3.1 坐标统一（v0.9.4，修 P1–P4）

- **引擎侧**：`layer_boxes` 增加 `max_edge` 入参（与 `render_with_overrides` 同语义），并返回/附带画布帧；新增或改造为返回 `{ frame: [w,h], boxes: [...] }` 的稳定结构（旧字符串数组调用点一并升级，不保留歧义双 API）。
  - 参考实现：`crates/framegeist-core/src/boxes.rs`（`layer_boxes_json` 已有 `cw/ch` 与 `layer_box` 管线，直接把 `opts.max_edge` 贯通即可）。
  - `canvas_size`（wasm `lib.rs:195`）同步支持 `max_edge`。
- **编辑器侧**：`refreshBoxes()`（`web/editor.js:448`）必须使用**当前显示渲染**的 max_edge：
  - 预览模式：与 `fastPreviewRgba` 一致的 1600 长边（抽为常量 `PREVIEW_MAX_EDGE`，`web/app.js:1416` 改为引用）；
  - 非预览/导出尺寸：`exportMaxEdge()`（`web/app.js:213`）。
  - 单次渲染令牌（renderToken）内同步刷新盒子，避免「旧图 + 新盒」。
- **几何消费方**：`imgRect()`/`canvasFrame()`/`canvasToLocal()`/`drawOverlay()`/`hitTest()`/拖拽/缩放/旋转全部改为从**同一 `viewportTransform` + 显示帧**推导；overlay 置于屏幕空间（不随 `applyZoom` 缩放），手柄固定 10px 视觉/≥24px 命中。
- **删除自动平移**：移除 `web/app.js:1588 panIntoView` 与 `web/editor.js:429/:779` 调用；新增「定位到选中」按钮（点击后最小平移，保证对象与画布主体可见）。
- **验收探针**：对每个图层断言 `overlay 盒中心 ≈ 引擎盒（按显示帧换算）±2px`；真实鼠标点击实物中心 → 命中该层；点击空白 → 取消选中；选中任意层后 `zoom` 不变；`visibleRatio ≥ 0.6`。

### 3.2 排版 v3 + 引擎能力（v1.0.0，修 P6）

- 新增引擎能力：**信息块自动拟合**——给定留白区（画布 extend padding 或模板留白矩形）与字段列表，自动排版 ≤3 行、块高/宽 = 留白区 2/3、字号自动求解（含上下限、行距、字距、对齐、灰度），确定性输出（同输入同结果，便于基线与帧字节一致性）。
- 模板 schema 扩展：`info_block`（side: left/right/bottom、fields 顺序与优先级、间距、对齐、字号上下限）；`docs/schema/` 与 `docs/TEMPLATE-SPEC.md` 同步；用户自传模板向后兼容（无 `info_block` 时按旧字段渲染）。
- DESIGN-LANGUAGE v3 重写：尺寸体系、字号阶、留白区间、行数规则、徽标尺寸与位置、对比度（沿用 ui-contrast 门禁）、中英混排规则。

### 3.3 徽标官方核对（v1.0.0，修 P5）

## 6. 反模式清单（本次教训，禁止重犯）

1. **合成事件自洽**：用与被测实现相同的错误映射推导点击坐标 → 全绿假通过。画布交互一律真实输入事件。
2. **坐标帧混用**：natural/layout、原图/预览/导出/全分辨率混算。任何几何先声明帧，再换算。
3. **只看门禁不看实物**：全绿 ≠ 正确；关键 UI 变更必须截图/像素核对。
4. **选中自动平移**：把画布推出视口；已废除。
