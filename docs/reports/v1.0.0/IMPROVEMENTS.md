# FrameGeist v1.0.0 改善提案（竞品调研产出）

> 依据：`docs/V1.0.0-CONSTRAINTS.md` §3.4 与决策 Q20（v1.0.0 顺带实施 2–3 个低成本高收益提案，其余入 backlog）。
> 来源：同目录 `RESEARCH.md` 的结论 C1–C10（对比 8 家竞品与 v0.9.4 实况）。
> **本报告明确标记 3 条为「低成本高收益，建议 v1.0.0 实施」：P1 导出预设、P2 批量导出命名规则、P3 快捷键增强。**其余 5 条为高优先级 backlog（建议 v1.1+）。
> 成本口径：1 人日 = 熟悉本仓库的开发者约 6 小时有效编码；估算**含**定向 E2E 断言、i18n（4 locale）与文档更新，不含发布流程。
> 红线约束：不引入运行时框架；不改 E2E 依赖的 id/class；拖拽不得作为唯一路径（WCAG 2.5.7）；不改模板渲染语义（确定性 / 帧字节一致）。

## P1 导出预设（含一键多尺寸） ✅ 建议 v1.0.0 实施

- **问题 / 机会**：竞品（VSCO 的 Recipe、Lightroom 的 Export Preset、Photoroom 的社媒尺寸）都把「格式 + 尺寸 + 质量 + 水印 + 元数据」打包成可命名、可切换的预设。我们只有设置页里的默认值与导出面板的下拉项，每次换用途（朋友圈 / 归档 / 客户交付）都要重新点一遍；分享要 2K、归档要原图时得导出两次。
- **方案**：
  1. 设置页新增「导出预设」区：预置 4 套只读预设（微信分享 · 2K JPEG；社媒 · 4K JPEG；归档 · 原图 PNG；网页 · 4K WebP），用户可「另存为」自定义预设（名称 + 上述参数），存 `fg-settings-v1` 的新字段 `exportPresets` / `activePreset`。
  2. 导出面板顶部加一行预设 chip；点 chip 即写回 `#exportSize` / `#exportFormat` 与设置，导出栏 `#exportBarInfo` 同步显示（例：`社媒 · 4K · JPEG`）。
  3. 预设可选「多尺寸一次性导出」：勾选后按列表顺序导出多份（2K + 原图），复用现有 `uniqueName` 去重。
  4. 不改变渲染调用：仍走 `render_with_overrides(..., exportMaxEdge(), settings.keepGps)`。

```
┌ 导出 ────────────────────────────────┐
│ 预设  [微信2K] [社媒4K] [归档原图▾]  │  ← chip 一行，可横向滚动
│ 输出尺寸  4K · 3840          ▾      │
│ 格式      JPEG               ▾      │
│ ☑ 同时导出 2K 分享版（多尺寸）       │
│ [ 批量导出 ]      [ 导出 JPEG ]      │
└──────────────────────────────────────┘
```

- **收益**：导出路径从 3–4 次点选降到 1 次；「分享 + 归档」一次完成；为后续 CLI / 桌面端复用同一预设结构留出 schema。
- **成本**：1.5–2 人日（设置 UI + 导出面板 + 状态同步 + 4 locale + E2E 断言：切预设后导出帧长边正确、多尺寸产出 2 个文件）。
- **风险**：设置结构新增字段的向后兼容（只增不改，旧值回退默认）；chip 过多导致面板拥挤（限制 6 个，超出收进下拉）；多尺寸导出放大内存峰值（仅对 ≥24MP 提示，且串行执行）。
- **是否建议 v1.0.0 实施**：**是**（低成本高收益）。

## P2 批量导出命名规则 ✅ 建议 v1.0.0 实施

- **问题 / 机会**：批量导出的文件名是竞品（Photoroom / Lightroom / Canva）共同的隐性痛点，也是我们 CLI `batch` 与 Web 批量导出的断点：目前只有 `uniqueName()` 重名去重，用户拿到一堆 `IMG_1234.jpg` 无法区分「加了什么模板、什么尺寸」。
- **方案**：
  1. 批量导出前弹出一个轻量对话框（可记住选择）：命名模板输入框 + 可用 token 提示 + 实时预览前 3 个文件名 + 冲突策略（追加序号 / 覆盖 / 跳过）。
  2. token 集合（保持最小）：`{name}` 原文件名、`{tpl}` 模板 id、`{tplName}` 模板名、`{date}` 导出日期、`{seq}` 序号、`{size}` 长边、`{fmt}` 格式。默认：`{name}_{tplName}_{size}`。
  3. 非法字符（`\ / : * ? " < > |`）自动替换为 `-`；总长截断到 180 字符防 Windows 长路径；预览区即时展示最终名。
  4. Web / Tauri 共用同一命名函数；CLI `batch` 后续复用同一 token 语义（本提案先不动 CLI）。

```
┌ 批量导出命名 ────────────────────────────┐
│ 模板  {name}_{tplName}_{size}            │
│ token  {name} {tplName} {date} {seq}     │
│                    {size} {fmt} {tpl}    │
│ 预览  DSC01234_经典白边_3840.jpg         │
│       DSC01235_经典白边_3840.jpg         │
│ 冲突  (•) 追加序号  ( ) 覆盖  ( ) 跳过   │
│                    [ 取消 ]  [ 开始导出 ]│
└──────────────────────────────────────────┘
```

- **收益**：批量产物可检索、可交付；减少「导出后再改名」的重复劳动；与 P1 的多尺寸导出天然配合。
- **成本**：1–1.5 人日（对话框 + 命名函数 + 预览 + 4 locale + E2E：token 替换、非法字符、冲突策略各 1 断言）。
- **风险**：token 语义一旦发布即需稳定（先冻结最小集合，扩展只增）；中文文件名在部分旧系统的编码（沿用 UTF-8 且不碰 `check-utf8` 流程）；对话框打断「一键导出」心流（提供「记住选择，不再询问」）。
- **是否建议 v1.0.0 实施**：**是**（低成本高收益）。

## P3 快捷键增强 + 速查表 ✅ 建议 v1.0.0 实施

- **问题 / 机会**：Canva / Lightroom 的编辑器都有完整的键盘通路与速查入口；我们目前只有方向键微调、Ctrl+Z/Y、Esc、空格平移、Ctrl+滚轮、Ctrl+,。高频动作（导出、适应窗口、100%、切换图层、切换侧栏 Tab）都还要用鼠标。
- **方案**：
  1. 新增快捷键（输入框聚焦时一律不触发）：
     - `E` 导出（等价 `#exportBtn`）、`Ctrl+Shift+E` 批量导出；
     - `F` 适应窗口、`0` 100%、`+` / `-` 缩放（等价 `#zoomIn` / `#zoomOut`）；
     - `L` 定位到选中（等价 `#locateSel`）；`Ctrl+D` 取消选中；
     - `[` / `]` 在图层列表上下切换选中；`Tab` / `Shift+Tab` 切换左侧栏 Tab。
  2. `?`（Shift+/）打开「快捷键速查」浮层：分组（画布 / 图层 / 文件 / 通用）+ 当前平台修饰键（Mac 显示 ⌘）；浮层内搜索框可选做。
  3. 设置页「关于」区加入速查表入口；空状态提示一行「按 ? 查看快捷键」。

```
┌ 快捷键 ───────────────────────  [×] ┐
│ 画布   F 适应窗口   0 100%   +/- 缩放│
│        L 定位到选中 空格 临时平移     │
│ 图层   [ ] 切换图层  Ctrl+D 取消选中 │
│        ←↑→↓ 微调（Shift ×10）        │
│ 文件   E 导出       Ctrl+Shift+E 批量│
│ 通用   Ctrl+Z/Y 撤销重做  ? 本表     │
└──────────────────────────────────────┘
```

- **收益**：重度用户（批量 / 修多张）效率显著提升；`?` 速查表同时降低新用户学习成本；为后续「键盘替代拖拽」的 WCAG 要求补足路径。
- **成本**：1.5 人日（按键路由 + 速查浮层 + 4 locale + E2E：每个新快捷键 1 断言，含输入框内不触发）。
- **风险**：与浏览器保留键冲突（避开 `Ctrl+S` / `Ctrl+P` 等；`E` / `F` / `L` 在输入框聚焦时禁用）；快捷键与既有方向键逻辑的作用域冲突（统一在 `window` capture 层做一次守卫判断）；速查表需随版本维护（条目写在单一常量表，UI 由表生成）。
- **是否建议 v1.0.0 实施**：**是**（低成本高收益）。

## P4 模板收藏与「我的集合」

- **问题 / 机会**：Canva 的模板墙是「搜索 + 分类 + 收藏 + 最近」四件套；我们已有搜索（`#tplSearch`）与「最近使用」分类（`fg-recent-v1`），缺收藏与自定义集合。品牌库已有收藏 / 最近（`fg-brand-fav-v1`），可复用同一交互模式，用户心智一致。
- **方案**：模板卡片右上角星标（hover / 触屏长按显示）；分类栏新增「收藏」与「我的集合」；集合为有序模板 id 列表，支持重命名 / 删除；数据存 `fg-tpl-fav-v1` / `fg-tpl-collections-v1`（只增不改）。集合可导出为 `.fgt` 清单（复用现有模板导入导出通道）。
- **收益**：192 套模板的选择成本下降；工作室用户可按客户 / 项目组织模板；与「最近使用」互补。
- **成本**：2 人日。
- **风险**：分类栏 DOM 若与 E2E 断言耦合需先核对（不得改既有 id）；收藏状态与用户模板（`fg-user-templates-v1`）的边界要清晰（收藏只存引用，不复制模板）。
- **是否建议 v1.0.0 实施**：否（backlog，建议 v1.1）。

## P5 品牌包（徽标 + 水印 + 默认值）

- **问题 / 机会**：Photoroom 的 Brand Kit 与 Canva 的品牌套件把 Logo / 颜色 / 字体统一管理；今日水印相机的「团队统一水印」说明多品牌 / 多项目切换是真实需求。我们已有 75 项徽章库、水印参数（高度 / 边距 / 间隔）与文字默认值（设置页），但没有「一套配置」的概念，每次换项目都要手动复原。
- **方案**：新增「品牌包」概念：名称 + 徽标 asset（内置徽章 id 或用户 Logo）+ 水印参数 + 文字默认值（字体 / 字号 / 颜色）+ 导出预设引用（P1）；作用域为「当前会话默认」，可手动应用到选中图层；存 `fg-brand-kits-v1`。模板作者可在模板内声明推荐品牌包（可选字段，v1.0.0 不动 schema，仅 UI 层记录偏好）。
- **收益**：工作室 / 多品牌用户一次切换；与 C9 场景化入口配合（「客户交付」品牌包 = 徽标 + 归档预设）。
- **成本**：2–3 人日（含 UI + 存储 + i18n + E2E）。
- **风险**：与模板自带水印 / 字段的优先级冲突（规则：品牌包只改「用户可改」的参数，不覆盖模板声明字段）；数据迁移与清理（设置页「本地数据管理」需新增一项清空）。
- **是否建议 v1.0.0 实施**：否（backlog，建议 v1.1）。

## P6 留白可视化与遮挡提示

- **问题 / 机会**：白框相机 / VSCO 的「打开即好看」来自默认参数；我们的 Step 3 引擎会新增「自动拟合空白区」，但如果不把引擎的几何意图画出来，用户只会看到文字「突然变了」，也不理解 2/3 规则与同侧 ≤3 行约束。
- **方案**：编辑器叠加层新增**只读**留白可视化（可开关，默认关）：用半透明色块显示检测到的留白区、虚线框显示 2/3 拟合框、文字块越界 / 与照片像素重叠时给出角标警告（点击跳到属性面板）。几何**只消费引擎输出**（Step 3 的 info_block 结果），编辑器内不重算，保证与导出一致。CLI 侧 `framegeist lint`（模板作者用，检测留白不足 / 遮挡）列为 v1.1。
- **收益**：让 Step 3 的能力可见、可解释；模板作者与用户共用同一套几何语言；减少「为什么文字这么小」的困惑。
- **成本**：1.5 人日（只读 overlay + 开关 + i18n + E2E 几何断言；不含 CLI lint）。
- **风险**：与导出帧不一致（必须复用 `boxFrame` / 显示帧坐标，遵守 §2 坐标单一事实来源红线）；可视化元素可能被误认为可编辑对象（用不同配色 + `pointer-events: none`）；性能（仅绘制矩形，无重渲染）。
- **是否建议 v1.0.0 实施**：否（backlog，建议 v1.1；若 Step 3 样张审核顺利，可顺带做只读版）。

## P7 粘贴 / 拖拽落点导入

- **问题 / 机会**：Canva / Lightroom 支持粘贴与拖拽导入；我们已有 dropzone（`dz` 的 drop 监听）与拖拽套模板，但缺 `Ctrl+V` 粘贴图片、也缺「拖到画布落点」（现在只能拖到固定 dropzone）。
- **方案**：`window` 级 `paste` 监听（从剪贴板取图片文件，复用 `acceptFiles`）；画布 `drop` 命中测试：落在画布内时按落点插入（模板帧模式下等价「替换照片」，自由拼贴下插入到该位置）；拖拽悬停时显示落点预览框；保留按钮入口（WCAG 2.5.7）。
- **收益**：截图 → 加框 → 导出 的路径缩短一半；自由拼贴的排版效率提升。
- **成本**：1.5–2 人日。
- **风险**：剪贴板中的 HEIC / 多文件处理（沿用现有 HEIC 转换）；落点插入与自由拼贴拖拽的手势冲突（区分「外部拖入」与「内部拖动」用 `dataTransfer.types`）；不得让拖拽成为唯一路径（保留「添加照片」按钮与文件选择）。
- **是否建议 v1.0.0 实施**：否（backlog，建议 v1.1）。

## P8 长按对比原图

- **问题 / 机会**：VSCO / Lightroom 的「长按看原图」是极低成本、极高感知的功能，用来判断边框 / 水印是否喧宾夺主。
- **方案**：按住 `\` 或长按画布（触屏 500ms）时，叠加层临时显示原图（照片层不套模板）；松开恢复；按钮化替代：工具栏加「对比」开关。原图复用已解码 RGBA 缓存，不新增解码。
- **收益**：决策更快，避免导出后才发现问题。
- **成本**：0.5–1 人日。
- **风险**：60MP 原图 RGBA 缓存的内存峰值（仅在已缓存时启用，否则降级为快速预览帧对比）；触屏长按与既有手势冲突（优先用键盘 / 按钮路径）。
- **是否建议 v1.0.0 实施**：否（backlog，建议 v1.1；若 P1–P3 提前完成可临时纳入）。

## 实施顺序与依赖（v1.0.0 内）

1. **P3 → P1 → P2**：P3 只加快捷键路由，先做可立刻验证；P1 提供预设结构，P2 的命名对话框引用 P1 的预设名（如 `{preset}` 作为可选 token，可延后）。
2. P1 / P2 / P3 全部只动 `web/` 的 UI 与设置组装层，**不改** `crates/`、模板 JSON、渲染调用参数语义；发布说明中并入 v1.0.0 条目。
3. 门禁补充：新增 E2E 断言（每提案 ≥2 条）；i18n 4 locale 同步；不改任何既有 id/class；发布前跑 `check-utf8`。

## 明确不做（本次调研的负向结论）

- 不做账号 / 云同步 / 协作 / 评论（与零上传红线冲突）。
- 不做生成式 AI 抠图、背景生成、滤镜调色（与离线优先、确定性渲染、v1.0.0 范围冲突）。
- 不做素材 / 贴纸商店与付费模板（MIT 全免费口径）。
- 不把水印压在照片像素上（红线：文字只落留白 / 边框区）。
- 不在 v1.0.0 内扩展模板 schema（P5 的品牌包字段留到 v1.1，避免与 Step 3 的 `info_block` 扩展争抢审核窗口）。
