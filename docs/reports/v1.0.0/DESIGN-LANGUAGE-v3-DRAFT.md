# FrameGeist 设计语言 v3（草案 · 待审核）

> 状态：**草案**，仅用于 STOP 1 审核，不覆盖现行 `docs/DESIGN-LANGUAGE.md`（v2）。
> 审核通过后：本文件内容替换 v2 文档并升为 v3，同时驱动 192 套模板全量重排（Step 5）。
> 依据：`docs/V1.0.0-CONSTRAINTS.md` §1（24 项决策）与 §3.2（排版规范）。

## 0. v2 的问题与 v3 的目标

用户反馈（原文，契约 §0）：
1. 「目前的字体大小和布置仍然不符合美学设计，文字全部放在图片的一侧，要么集中在左侧要么集中在下侧」；
2. 「文字允许三行以内自由排布，文字大小应该取正好填满空白部分 2/3 的高度（在下侧时）或宽度（在左侧时）」。

v2 的排版是**逐层绝对定位**：每层文字自带字号与偏移，模板作者手工凑数 → 结果是字号偏小、成组文字挤在角落、留白比例失控。
v3 把「信息块」变成**一等概念**：一套模板声明**一个**信息块（`info_block`），引擎在**指定的留白区**里自动求解字号与行距，让可见文字块**正好占满该区 2/3**。

## 1. 核心原则

1. **照片是主角**：文字只出现在画布扩展出的留白区（`canvas.mode = "extend"`），**永不覆盖照片像素**。
2. **单侧成组**：一套模板的全部文字 + 徽标集中在**同一侧**（`left` / `right` / `bottom`），不跨边、不混排（上侧不用于信息块）。
3. **≤3 行**：信息块最多三行，按角色（display / support / detail）组织，行数由字段可用性自动收敛（字段缺失则该行隐藏）。
4. **2/3 拟合**：可见文字块填满留白区 —— 下侧取**高度**的 2/3，左/右取**宽度**的 2/3；字号由引擎求解（不写死）。
5. **确定性**：同一输入 → 同一几何与像素（无随机、无迭代上限依赖），并在 `boxes` 几何 API 中**完全一致**。
6. **向后兼容**：无 `info_block` 的模板继续按 v2 的逐层路径渲染，字节不变。

## 2. 留白区（band）规范

| 侧 | 典型扩展量（占照片对应边） | 说明 |
|---|---|---|
| bottom | 0.20 – 0.32 | 最常用；适合机型号 + 参数行 + 日期 |
| left | 0.24 – 0.34 | 竖构图/杂志感；块在区内**水平居中**、垂直居中 |
| right | 0.24 – 0.34 | 同 left（镜像），文字默认右对齐 |

- 留白区 = 扩展出来的整条矩形（不含照片）；下侧区 = `(pad_left, photo_h) → (canvas_w − pad_right, canvas_h)`。
- 背景：`canvas.background.type = "solid"`（或 `tint`）；深色模板使用深底浅字。
- 信息块在区内**居中**（下侧可指定 `align: left|center|right` 决定块的横向落点；左/右固定居中，`align` 决定块内每行的对齐）。

## 3. 字阶与角色（v3）

| 角色 | 相对字号 | 字重 | 字距 | 用途 |
|---|---|---|---|---|
| `display` | 1.00 | 600 | −0.02 em | 主体：机型 / 地点 / 主标题 / 大日期 |
| `support` | 0.72 | 400 | 0 em | 技术参数：焦距 · 光圈 · 快门 · ISO |
| `detail` | 0.58 | 400 | +0.08 em | 次级：日期 / 序列号 / 作者 |

- **基础字号由拟合求解**：满足 2/3 规则，并 clamp 在 `sizeMin`（默认 0.0095）与 `sizeMax`（默认 0.12，均为照片高度分数）之间。
- 行距：`lineHeight`（默认 1.25，允许 0.5–4.0）；行间空隙 = `(lineHeight − 1) × 字号`，clamp 0.15–0.6。
- 字体：`font.family` 为候选族列表（1–8）；`font.weight` 若给出则覆盖角色字重。
- 字号仍以**照片高度**为基准（与 v2 一致），保证不同分辨率下观感一致。

## 4. 字段与顺序

- 信息块按 `lines[]` 顺序自上而下排布，每行一个表达式 + 可选 fallback + 角色。
- 推荐组合（模板作者按题材选择）：
  - 相机系：`display=model_pretty`、`support=fmt('{focal}mm · f/{aperture} · {shutter} · ISO{iso}')`、`detail=date`
  - 旅行系：`display=地点/标题`、`support=date`、`detail=序列号/作者`
  - 极简系：`display=model_pretty`、`support=date`（两行）
- 表达式为空且无 fallback → 该行隐藏；三行全空 → 整个信息块不绘制（不报错）。

## 5. 对齐与位置

- 下侧：块整体在区内**垂直居中**（上下各留 1/6），横向按 `align`；块内每行按 `align` 对齐。
- 左/右：块在区内**水平 + 垂直居中**；`align` 控制块内每行对齐（`right` 侧默认右对齐）。
- 行内不换行（单行单表达式）；超长文本由拟合自动缩小以不越出区宽/区高。

## 6. 颜色与对比度

- `color: "auto"` → 引擎按留白区背景亮度自动取深/浅文字色；也可显式 `#RRGGBB`。
- 目标对比度：正文文字 ≥ 4.5:1（WCAG AA），大字号 display 行 ≥ 3:1；门禁 `check-ui-contrast` 覆盖。
- 背景色与文字色成对出现在样张中，禁止紫系（v2 §4 的禁紫规则延续）。

## 7. 徽标规则（与文字同侧）

- 徽标（品牌/系列/游戏字标）必须落在**信息块同一侧**的留白区内，与文字块保持 ≥ 1 个字号的安全间距，不得压住文字或照片。
- 尺寸延续 v2：徽标高度 ≥ 6% 照片高（默认 6.5%），最大宽度 ≤ 44% 照片宽，不透明度 0.7–1.0。
- v1.0.0 的 47 项徽标样式核对另见 `docs/reports/v1.0.0/brand-audit.md`（STOP 2）。

## 8. 兼容与迁移

- 旧模板（无 `info_block`）继续按 v2 逐层渲染，**像素不变**；`docs/DESIGN-LANGUAGE.md` 的 v2 规则在迁移期仍对旧模板有效。
- 迁移策略（Step 5）：按题材分批把 192 套重排为 info_block 形态 → 重渲 576 张样片 + 视觉基线全量重生成 + 对比图（v0.9.4 → v1.0.0）。
- 每套模板保留 `meta.version` 递增，便于回退与幂等重放（`tools/apply-v100-typography.mjs`）。

## 9. QA 门禁（自动断言）

1. 2/3 拟合：可见文字块高（下侧）/宽（左·右）与目标差 ≤ 5px；
2. ≤3 行；全部行同侧；
3. 不越出留白区、不覆盖照片像素（`boxes` 几何断言）；
4. 最小字号 ≥ 0.0095 × 照片高；最大 ≤ 0.12；
5. `boxes` 与渲染像素的墨迹包围盒一致（±2px）；
6. 同输入两次渲染字节一致（确定性）；
7. 对比度门禁 + 字形覆盖门禁通过。

## 10. 待审问题（请用户裁决）

1. **下侧块的横向落点**：默认 `left`（左对齐）是否合适？还是 `center` 更符合观感？
2. **左侧/右侧的默认对齐**：块在区内居中 + 行右对齐（right 侧）是否认可？
3. **字号上限 0.12**（照片高 12%）是否足够？大标题类模板是否需要更高（例如 0.16）？
4. **三行信息块的字段优先级**：`display` 用机型还是日期？（当前样张用机型/标题）
5. **深色模板**是否纳入 v1.0.0 的模板库（样张 s02/s04 已展示深底浅字）？
